# 工作流程说明

本文件只定义经营分析任务的执行顺序与关键判断。  
角色定位、时间口径、报告模板、写作要求等内容，按 `SKILL.md` 与相关 references 执行。

---

## 1. 先检查三要素

正式查询前，先确认以下三项是否齐全：
- 分析对象
- 时间范围
- 分析目的

若缺少任意一项，先追问，不能直接查询。

推荐追问方向：
- 看哪个组织、区域、中心或节点
- 看哪个月份、哪个学年，还是看累计
- 是查单项指标、看目标达成，还是做完整经营分析

---

## 2. 先做节点标准化

正式查询前必须先调用 `resolve_org_nodes`。  
禁止跳过。

节点处理规则：
- 只有一个匹配结果：直接使用
- 有多个候选节点：让用户确认
- 无匹配结果：请用户补充更明确的关键词或上级组织信息

未确认节点前，不得直接查询经营数据。

---

## 3. 判断任务类型并制定查询方案

默认主查询工具：`query_with_hierarchy`

工具使用顺序：
1. `resolve_org_nodes`
2. `query_with_hierarchy`
3. `query_monthly_plan`（仅在目标/计划类问题中使用）
4. `query_biz_data`（仅兜底）

### 3.1 简单指标查询
适用场景：
- 某节点某月单一指标查询

处理方式：
- 只查用户指定指标
- 若隐含目标/达成判断，再补计划值

### 3.2 对比类查询
适用场景：
- 多节点对比
- 多月份对比
- 多指标对比

处理方式：
- 保证指标口径一致、时间口径一致
- 优先整理为 Markdown 表格
- 表格后补充简洁结论

### 3.3 分析类查询
适用场景：
- 经营分析
- 原因诊断
- 风险判断
- 月报 / 经营分析报告

处理方式：
- 不只查单一指标
- 查询“核心指标 + 关联指标”
- 默认支撑“结果—偏差—原因—判断—建议”输出

---

## 4. 月度经营分析的标准查询组合

如果用户要求某月经营分析、月报、月度复盘或经营诊断，不能只查单月。

至少包含：
1. 该月当月数据
2. 上月数据（用于环比）
3. 累计至该月数据
4. 如涉及达成判断，再补计划/目标数据
5. 如需解释结构或拖累点，再补拆分数据

例如“2026年2月经营分析”至少应考虑：
- 202602 当月
- 202601 当月
- 累计至 202602
- 必要时补 202602 月度计划 / 累计计划

具体时间口径与学年规则按 `SKILL.md` 执行。

---

## 5. 分析类任务的常用指标补齐

如用户要求分析、诊断、说明原因、评估经营情况，优先补齐以下指标：

### 5.1 规模
- `revenue`
- `headcount`
- `per_capita_revenue`

### 5.2 盈利
- `gross_profit`
- `gross_margin`
- `pretax_profit`
- `pretax_margin`

### 5.3 效率
- `labor_cost`
- `labor_cost_rate`
- `other_expense`
- `revenue_creation`
- `profit_creation`

### 5.4 目标达成
- 实际值
- 计划值 / 目标值
- 达成率
- 累计进度

若用户问月度突围计划、收入目标、税前利润目标，使用 `query_monthly_plan`。

---

## 6. 数据质量检查

正式分析前，先检查数据是否足够支撑结论。

### 6.1 空结果处理
若查询结果为空，按以下顺序排查：
1. 节点是否已标准化
2. 指标名称是否正确
3. `period_type` 是否正确
4. `period` 是否正确
5. 计划/实际口径是否选错

若存在明显修正方向，至少重试一次。  
只有排查并重试后仍为空，才能告知用户暂无数据。

### 6.2 截断处理
如果返回结果中 `total_records` 接近 `limit`：
- 优先增大 `limit`
- 或按节点 / 指标 / 时间拆分查询

不要基于疑似截断的数据直接得出最终结论。

### 6.3 缺失与异常处理
若出现以下情况，必须主动提示并限制结论强度：
- 关键指标缺失
- 口径不一致
- 数据逻辑矛盾
- 只有单点数据，无法支持趋势判断

---

## 7. 分析展开顺序

完成查询后，建议按以下顺序展开：

1. 结果  
2. 偏差  
3. 原因  
4. 判断  
5. 建议  

重点回答：
- 是规模问题、盈利问题、效率问题，还是结构问题
- 是短期波动，还是趋势性变化
- 是否影响全年/学年目标
- 下一步最该抓什么

---

## 8. 输出要求

### 8.1 普通分析输出
建议结构：
1. 核心结论
2. 关键数据
3. 偏差与原因
4. 经营判断
5. 管理建议

### 8.2 报告模式
若用户要求完整报告、月报或 markdown 报告：
1. 先读取报告模板
2. 再按需读取相关 references
3. 数据不足的章节保留但标记“待补充”或弱化结论
4. 不得编造数据，不得基于不完整数据输出强结论

### 8.3 表格与图表
- 多节点、多月份、多指标对比优先用 Markdown 表格
- 图表仅在明显优于文字/表格时输出
- 图表输出必须直接给出 `html` fenced code block
- 若数据不足、口径不一致或只有单点数据，跳过图表

---

## 9. 响应风格

保持以下风格：
- 专业
- 简洁
- 结论先行
- 面向管理层

不要只做数字堆砌。
