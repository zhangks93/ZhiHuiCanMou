# 图表输出规范（structured chart spec JSON）

在经营分析中，图表不再通过对话中的 ECharts HTML 渲染。
图表相关输出统一改为 **结构化 chart spec JSON**，供离线脚本直接生成 PNG 等图片资源。

## 基本原则
- 先有经营结论，再决定是否配置图表
- 一张图尽量只表达一个重点
- 图表服务于解释，不做装饰
- 数据不足、口径不一致、只有单点数据时，不强行出图
- 如表格更清楚，正文保留表格，图表部分只保留最有价值的 3-5 个 spec

## 输出方式
需要图表时，输出：
- 带 `json` 语言标签的 fenced code block
- 3-5 个 chart spec 组成的 JSON 数组，或等价的 `charts` 数组对象
- 使用结论式标题，不使用“图1 / 图2 / 图3”
- 序列数据完整，可被离线脚本直接消费

禁止输出：
- ECharts HTML
- 原始 HTML
- 伪代码
- “建议画一个图”这类占位性描述

## 图表选择建议
- **趋势**：`line`、`combo_bar_line`
  适合收入、利润、毛利率、人效等月度变化

- **对比**：`bar`
  适合节点、区域、业务之间的收入/利润/达成率对比

- **结构**：`stacked_bar`、`pie`
  适合收入结构、费用结构、区域贡献结构

- **偏差归因**：`waterfall`
  适合预算 vs 实际、利润偏差、费用偏差拆解

## chart spec 字段要求
每个 chart spec 至少包含：
- `id`
- `title`
- `summary`
- `chartType`
- `scope`
- `dimension`
- `metrics`
- `unit`
- `series`

其中：
- `scope` 明确统计口径与期间，例如“学年预算-当月-202602”
- `dimension` 明确横轴或分类维度，例如 `metric_category`、`node_name`、`expense_type`
- `metrics` 明确图中使用的指标键
- `series` 中必须包含可直接绘图的数据点

## `series` 建议结构
- `name`: 序列名称
- `type`: 序列图形类型
- `unit`: 当前序列单位
- `data`: 数据点数组

`data` 中建议至少包含：
- `label`: 类目名称
- `value`: 数值
- `target`: 可选，对照值或目标值
- `note`: 可选，补充说明

## 标题要求
优先使用“结论式标题”，例如：
- 当月收入基本达成，但利润转化仍弱于预算要求
- 重点单元贡献分化明显，头部单元支撑整体收入兑现
- 成本压力主要集中在人力与重点费用项，利润端承压仍需缓解

避免使用：
- 图1
- 收入图
- 统计图

## 什么时候不出图
以下情况通常不建议输出该图的 chart spec：
- 只有一个数据点
- 数据缺失明显
- 对比口径不一致
- 图表不会比正文或表格更清楚

## Agent 自主权
Agent 可以根据：
- 分析目标
- 数据结构
- 指标单位
- 展示重点

自主决定：
- 是否输出某张图
- 输出几张图
- 图表类型
- 序列拆分方式
- 是否排序、是否取 Top N、是否保留目标值

原则只有一个：**让 chart spec 更有效地支持经营分析结论，并能被离线绘图脚本稳定消费。**
