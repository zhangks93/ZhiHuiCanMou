# 完整报告生成规范

## 适用触发场景
当用户要求生成以下内容时使用：
- 分析报告
- 经营分析报告
- 月报
- 完整报告
- markdown 报告

---

## 必须先做的步骤

先调用 `read_file` 读取：

`/assets/financial-analysis/biz-analysis-report.md`

将读取到的模板作为结构基础，再结合实际查询数据进行填充、删减和写作。

---

## 报告主线

报告默认按以下主线生成：
1. 经营摘要
2. 年初预算完成情况总览
3. 年初预算详细分析
4. 成本分析
5. 重点项目 / 重点单元分析
6. 突围考核完成情况
7. 管理建议

不要再扩展成过多无关章节，也不要为了“完整”保留大量空章节。

---

## 详细度要求

### 年初预算部分
这是报告的主分析模块，必须写得更详细，重点回答：
1. 整体经营情况如何
2. 当月、累计、上月分别表现如何
3. 当月与累计必须分开写，不能把达成率、差额、同比混成一个口径不明的结论
4. 与年初预算值相比差异在哪
5. 成本费用如何影响利润
6. 哪些重点项目 / 单元表现较好，哪些形成拖累
7. 当前状态对学年目标有何影响
8. 同比变化如何，背后的经营含义是什么
9. 成本章节除人力成本外，默认覆盖餐饮支出、物资销售成本、车辆费用、能耗费、差旅费、业务招待费、其他支出等费用项

### 突围考核部分
这一部分可以简写，重点强调：
1. 核心指标完成情况
2. 达成率
3. 差额
4. 是否达标

突围考核部分不要求写成长篇归因分析。

---

## 写作原则

报告必须体现专业财务分析能力，而不是简单的数据拼接。

每个主要章节尽量回答：
1. 结果如何
2. 为什么会这样
3. 会带来什么经营影响
4. 下一步怎么办

并额外满足：
- 达成率、差额、同比、完成判断都要绑定到明确口径
- 同时写当月与累计时，优先拆成两个小节或两张表
- 不要用一个“预算达成率”列同时承载当月和累计口径

若查询结果中已经返回以下字段，必须显式利用：
- `budget`
- `completion_rate`
- `diff`
- `year_over_year`

不要只使用 `actual` 做静态描述。

推荐风格：
- 简洁
- 结论先行
- 面向管理层
- 财务分析视角明确

---

## 缺失数据处理规则

若某一字段缺乏支撑数据：
- 标记为 `【待补】`
- 不得编造数据
- 不得给出过强结论

若字段可由查询结果聚合或计算得到：
- 应先聚合 / 计算后写入报告
- 不要把原本可算出的值留作 `【待补】`

若某类数据数据库暂无：
- 标记为 `【数据库暂无此数据】`
- 可直接跳过整段无效展开

---

## 建议写法提示

在数据支持的前提下，适当体现：
- 三大区域 + 商业业务是增长极
- 后勤管理中心是基本盘

应在摘要和判断中体现：
- 增长极的拉动作用
- 基本盘的稳定作用
- 成本费用对利润的侵蚀或支撑

并主动计算和体现：
- 环比变化
- 同比变化
- 预算达成率与差额
- 重点项目 / 单元的贡献度或拖累度
