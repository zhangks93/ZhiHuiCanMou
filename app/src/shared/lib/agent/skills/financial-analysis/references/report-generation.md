# 完整报告生成规范

## 适用触发场景
当用户要求生成以下内容时使用：
- 分析报告
- 经营分析报告
- 月报
- 完整报告
- markdown 报告

## 必须先做的步骤
先调用 `read_file`，读取以下路径：

`/assets/financial-analysis/biz-analysis-report.md`

将读取到的模板作为结构基础，再结合实际查询数据进行填充、调整和写作。

## 报告原则
报告必须体现专业财务分析能力，而不是简单的数据拼接。

每个主要章节尽量回答以下问题：
1. 结果如何
2. 为什么会这样
3. 会带来什么经营或财务影响
4. 下一步怎么办

## 推荐报告逻辑
当数据条件允许时，优先采用以下分析结构：
1. 执行摘要
2. 总体经营表现
3. 预算执行与偏差归因
4. 收入与业务结构分析
5. 利润与盈利质量分析
6. 重点板块 / 区域 / 项目专题
7. 费用效率与成本控制
8. 年度目标达成预测
9. 改进建议与管理动作

你不需要死板保留模板中的每一个字段，可以根据数据情况适当调整表格和小节设置，以增强可读性和分析质量。

## 缺失数据处理规则
若某一章节缺乏支撑数据：
- 保留章节标题
- 标记为 `待补充`，或做结构性留白
- 不得编造数据
- 不得给出过强结论

## 写报告时需体现的业务背景
在数据支持的前提下，适当体现：
- 三大区域 + 商业业务是增长极
- 后勤管理中心是经营基本盘

应在摘要和判断中体现增长拉动与基本盘稳定的关系。

## 推荐报告风格
- 简洁
- 适合管理层阅读
- 结论先行
- 财务分析视角明确
- 避免空泛套话
