# 完整经营分析报告生成规范

仅用于完整报告、月报、markdown 报告和汇报材料。完整报告必须像经营汇报材料，不写成泛化摘要。

## 1. 数据主线

完整报告必须优先使用 `query_business_report_pack` 作为主数据源。若可用工具包含 `compose_business_report`，优先调用该工具；它会内部调用 `query_business_report_pack`、分章写作、合并并审核。若 `coverage.core_biz_data = missing`，不得生成完整报告，只输出缺数说明。

报告包字段使用优先级：
- 先看写作素材、章节简报和证据台账。
- 再看质量契约、断言规则和数据完整度矩阵。
- 核心表优先使用学年目标表、目标对标宽表、两层组织表、成本费用宽表。
- 结构与风险优先使用范围画像、直接下级、重点下钻单位、项目异常、重点单位卡片、差异排行和风险预警。
- 缺数说明只用于报告结尾。

关键结论必须能回溯到证据台账；需要人工补充的数据只能写成补数要求，不得写成已确认事实。

## 2. 章节结构

默认结构：
1. 经营摘要与学年目标判断
2. 目标对标与实际完成
3. 组织结构、贡献与拖累
4. 成本费用与效率
5. 风险判断与后续动作
6. 数据限制与待补说明

允许按组织范围和数据完整度合并小节，但不得省略核心经营判断。集团看区域 / 中心结构与贡献；区域 / 中心看下属单元差异；明细单位 / 项目不强行输出无意义下级构成。

## 3. 表格规则

数据充足时优先输出：
- 学年目标达成概率与风险表：只覆盖营业收入、税前利润。
- 目标对标宽表：实际值只展示一次，并列展示学年预算与突围考核。
- 组织构成 / 贡献 / 缺口表：至少一张覆盖两层组织；若存在二级下属，正文尽量呈现有数据的第二层单位，并给出收入、税前利润、人力成本或毛利率等数字；若无二级下属，在数据限制中说明。
- 成本费用或效率宽表。
- 风险动作表。

表格服务于判断，不为凑数量。完整报告默认按详版写作：有数据的下钻单位尽量呈现，组织结构章节优先覆盖贡献前列、拖累前列、利润为负、收入或利润完成率偏低、费用超预算的单位。每张核心表后至少写 2 条带数字、对象、原因或风险的分析。

## 4. 缺失数据与禁用

- 终稿不得出现内部口径枚举、内部字段名、工具字段名、数据表名或英文状态词；统一写“学年预算”“突围考核”“达标”“关注”“风险”“缺数”等中文表达。
- 终稿不得出现“叶子节点、节点、node、leaf、worker、JSON、字段名、表名、数据结构”等非业务表达；统一写“单位、项目、明细单位、下属业务单元、第二层单位”等业务表达。
- 当月宽表允许实际值只展示一次；截至当月累计和学年目标累计必须分别展示学年预算实际值、突围考核实际值，并基于各自实际值解释完成率和差额。
- 不输出 `【人工补充】` 或大面积待补占位表。
- 应收账款、资金计划、核心费用专项明细只在“数据限制与待补说明”集中列出补数要求。
- 系统已有的人力成本、工资、物资成本、车辆费用、能耗费、差旅费、招待费等指标必须正常分析，不能写成待补。
- 普通完整报告不输出图表 JSON；只有用户明确要求 chart spec 时才读取 `chart-guidance.md`。

## 5. 自审

输出终稿前：
1. 按 `report-quality-rubric.md` 自审。
2. 调用 `audit_business_report` 审核 Markdown 初稿。
3. 修复 error 级问题；warning 级问题若因数据缺失无法修复，在数据限制中说明。

## 6. 分章写作模式

当使用 `compose_business_report` 时，报告由总控工具拆成多个章节分别写作：
- 总控只查一次报告包；分章写作不得直接查询业务数据。
- 分章写作只使用对应章节简报、证据台账和裁剪后的表格。
- 各章节由总控按固定顺序合并，再执行质量审核。
- 若某个章节生成失败，总控使用证据台账生成保守章节，不得中断整份报告。
