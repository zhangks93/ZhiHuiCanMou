# 完整报告生成规范

只用于“完整报告 / 月报 / markdown 报告 / 汇报版材料”。这里不重复查询规则与分析句式；查询前置看 `workflow.md` 与 `metrics.md`，表达强化看 `analysis-method.md`。

## 1. 起手动作

先和用户确认本次报告的：
- 分析对象
- 时间范围
- 报告目标
- 统计口径偏好
- 详版还是偏摘要版

先读取：

`/assets/financial-analysis/biz-analysis-report.md`

以模板为结构骨架，结合实际数据填充、删减，不保留空章节。
同一任务里，模板和各 reference 文件读取一次即可；已成功读取后，不得重复调用同一路径来“确认规则”。
完整报告默认按“详版”标准输出；若用户未明确要求摘要版，不得主动压缩成只保留表格和几句结论的简版。

## 2. 报告主线

默认章节：
1. 经营摘要
2. 年初预算完成情况总览
3. 年初预算详细分析
4. 重点项目 / 重点单元分析
5. 突围考核完成情况（含降成本费用分析）
6. 管理建议
7. 图表结构化配置

预算部分写得更详细；突围部分可以略短，但仍需完整呈现完成情况、差额、结构质量、偏差归因、降成本费用执行情况及其对利润的影响。

## 3. 最低交付要求

- 开头先给管理层可直接使用的经营摘要
- 当月、累计、上月分开表达，不混口径
- 显式使用目标值、达成率、差额、同比
- 至少保留 3 类核心数据表；数据充足时优先保留 4 类及以上
- 不能只给摘要和结论，缺少数据支撑
- 每个核心章节都要同时覆盖“数据呈现、经营判断、原因或影响”，不能只剩表格或只剩结论
- 合并章节后，不能因为“并入突围考核”就把降本费用分析压缩成一句话总结

建议优先保留的表：
- 核心经营指标总览表
- 年初预算达成对比表
- 重点项目 / 重点单元对比表
- 突围考核及降成本费用完成情况表

建议优先保留的分析段：
- 总体经营判断段
- 预算偏差归因段
- 重点单元贡献与拖累段
- 突围目标偏差与利润转化段
- 降本执行质量与重点压力项段

## 4. 自审后再交付

正式输出前，至少检查：
- 当月、累计、上月是否完整
- `fone` 与 `tuwei` 是否完整
- 结论是否有表格或数据支撑
- 口径、结论、数据是否一致
- 是否存在 AI 腔、口语化、宣传化表达
- 建议是否具体到动作、对象或推进方向
- 是否误把完整报告写成摘要版，导致归因、结构质量、影响判断明显不足
- 合并后的突围章节是否同时覆盖“完成情况”和“降本费用分析”，且两者都形成独立判断

发现问题先修正，再只展示终稿。

终稿结尾补一小段后续支持建议，例如：
- 继续补查某个重点单元
- 改成会议摘要版
- 补充图表
- 横向对比其他区域 / 部门

## 5. 缺失数据处理

- 可计算的值先聚合或计算后再写
- 数据库暂无的数据标 `【数据库暂无此数据】`
- 单个字段待补可标 `【待补】`
- 整章无支撑数据时，删除空展开，仅保留一句限制说明

## 6. 图表交付

需要图表时，再读取 `chart-guidance.md`。

完整报告默认在末尾追加“图表结构化配置”章节，输出 3-5 个结构化 chart spec JSON；若整体数据明显不足，可少于 3 个，但不能用占位图凑数。
