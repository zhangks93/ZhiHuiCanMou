# 经营分析报告质量 Rubric

终稿前先自审，再调用 `audit_business_report`。error 必须修复；warning 若因缺数无法修复，写入数据限制。

## 结构
- 是否覆盖经营摘要、目标对标、组织结构、成本费用、风险动作和必要的数据限制。
- 是否按 `scope_profile` 调整颗粒度，而非机械套模板。
- 是否包含报告包要求的两层组织分析；若没有二级下属，是否说明限制。
- 若报告包存在更深层级组织数据，是否尽量点名深层级单位，而非只停留在一级 / 二级摘要。

## 数据
- 是否优先使用写作素材、章节简报、证据台账和数据完整度矩阵。
- 是否同时处理当月、截至当月累计、学年目标累计中的可用数据。
- 是否同时覆盖学年预算和突围考核，且正文未暴露内部口径枚举、内部英文状态值、内部字段名或数据表名；必要业务缩写可保留。
- 分析判断是否优先使用突围考核完成情况，同时完整展示学年预算和突围考核。
- 当月实际值是否合并展示，累计实际值是否按学年预算与突围考核分别展示。
- 是否避免口径混写，关键数字是否有证据来源。
- 有数据的下钻单位是否尽量呈现，是否避免只写少数摘要性结论。

## 判断
- 每张核心表后是否有带数字依据的分析。
- 组织结构章节是否至少下钻两层；有二级下属时是否点名第二层单位并写出具体数字。
- 是否区分收入、利润、费用、效率、进度问题。
- 是否区分经营型单位与职能 / 支持型单位；职能 / 支持型单位是否按成本效率和费用执行分析，而不是因无营收或负利润直接定性为问题。
- 数据缺失时是否降低结论强度。
- 风险动作是否对应具体对象和证据。

## 禁止
- 编造应收、资金、核心费用专项数据。
- 在普通经营章节保留 `【待补】`、`【人工补充】`。
- 默认输出图表 JSON。
- 把完整报告写成摘要，或只输出表格不写分析。
- 在终稿中出现“叶子节点、节点、node、leaf、worker、字段名、表名、数据结构”等非业务表达。
