# 经营分析报告质量自审 Rubric

输出前必须逐项自审。

## 结构完整性
- 是否覆盖经营摘要、目标对标、实际完成、结构贡献、成本费用、风险动作？
- 是否根据组织层级调整颗粒度，而不是机械套固定章节？
- 专项数据缺失时，是否在结尾集中说明，而不是输出大量占位表或编造数据？

## 数据完整性
- 是否先查看 `writing_brief` 和 `data_completeness_matrix`？
- 是否同时覆盖当月、上月、累计中的可用数据？
- 是否同时覆盖 fone 和 tuwei？
- 是否包含 actual、target、completion_rate、diff？
- 是否出现口径混写？

## 颗粒度
- 是否使用 `scope_profile` 判断当前是集团、区域、中心还是叶子节点，并调整分析颗粒度？
- 集团层级是否点名区域/中心贡献和拖累？
- 区域/中心层级是否点名下属单元差异？
- 叶子节点是否避免强行输出无意义的下级构成表？
- `unit_cards` 中的重点单位是否说明了 `selection_reason`？

## 业务判断
- 每张核心表后是否有判断？
- 判断是否有数字依据？
- 是否区分收入问题、利润问题、费用问题、进度问题？
- 是否把缺数对结论强度的影响说清楚？

## 风险闭环
- 黄色/红色预警是否有建议动作？
- 建议是否对应具体对象？
- 对人工补充数据是否提示“补数后复核”？

## 禁止
- 禁止保留普通经营章节的 `【待补】`。
- 禁止编造应收、资金、核心费用专项数据。
- 禁止默认输出图表 JSON。
- 禁止把完整报告写成摘要。
- 禁止只输出表格不写分析。
