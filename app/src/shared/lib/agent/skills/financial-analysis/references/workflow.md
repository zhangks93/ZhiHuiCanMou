# 工作流程说明（执行清单）

**文档分层**：[主系统提示 `prompt.md`](../prompt.md) 含角色定位、时间口径、查询规则、输出与禁止项等完整规范。本文件只保留执行顺序与自检清单，不重复展开细则；若与主提示冲突，以 `prompt.md` 为准。

---

## 执行清单

### 1. 三要素
- [ ] 已明确分析对象、时间范围、分析目的
- [ ] 缺一则先追问，不直接查询

### 2. 节点标准化
- [ ] 范围不清、用户切换对象、或 scope 置信度不足时，已调用 `resolve_org_nodes`
- [ ] 多候选时已让用户确认
- [ ] 高置信度且未变更的 scope 已复用，无重复解析

### 3. 查询主线
- [ ] 已按两个统计口径查询：`fone` 年初预算、`tuwei` 突围考核
- [ ] 每个统计口径都补齐了：当月、累计、上月
- [ ] 无依赖的查询已优先并行发起
- [ ] `query_with_hierarchy` 已优先返回树状结果，而不是再让模型自己重建层级
- [ ] 需要局部分析时，已直接查询目标节点子树；需要整体分析时，已获取整棵树

### 4. 指标覆盖
- [ ] 已覆盖核心经营指标：收入、毛利、毛利率、税前利润、税前利润率
- [ ] 经营分析 / 月报 / 完整报告场景下，已默认补齐人力与费用细项指标，而非只查人力成本
- [ ] 费用项已覆盖餐饮支出、物资销售成本、车辆费用、能耗费、差旅费、业务招待费、其他支出等可用指标
- [ ] 重点项目 / 单元分析需要时，已补结构拆分数据
- [ ] 返回中的 `target_value`、`completion_rate`、`diff`、`yoy` 已纳入分析，不只读取 `actual`

### 5. 数据质量
- [ ] 空结果已排查节点、期间、口径并重试
- [ ] 疑似截断已增大 `limit` 或拆分查询
- [ ] 缺失或矛盾数据已提示，并限制结论强度
- [ ] 累计 period 已从 Runtime Data Context 的 `cumulative_periods` 中选取真实合法值，而非自行推算

### 6. 报告输出
- [ ] 年初预算部分作为主分析模块，写得更详细
- [ ] 突围考核部分控制篇幅，重点强调完成情况
- [ ] 输出中明确写出当月、累计、上月的对比关系
- [ ] 达成率、差额、同比、完成判断均已绑定明确口径，不存在“当月/累计”混写
- [ ] 输出中明确展示预算值、达成率、差额、同比变化
- [ ] 对可计算的汇总值、环比、同比、占比、贡献度已先行聚合计算，不留给用户手工补齐
- [ ] 报告结构优先为：经营摘要、预算总览、预算详细分析、成本分析、重点项目/单元、突围完成情况、管理建议
- [ ] 完整报告场景在正式输出前已做一次数据与文本自审校验
- [ ] 已根据自审结果修正口径、结构、表格、判断和表达，再输出终稿
- [ ] 自审时已逐项核对：当月、累计、上月、`fone`、`tuwei`、同比
- [ ] 已保留至少 3 类核心数据表；若数据充足，已保留 4 类及以上
- [ ] 若发现口径混写、表格缺失、结论与数据不一致，已先修正再输出
- [ ] 若关键章节数据不足，已明确标注数据限制并降低结论强度
- [ ] 终稿关键段落已体现“结果判断 → 差异分析 → 原因拆解 → 风险提示 → 后续动作”的经营分析逻辑
- [ ] 终稿表述已清除 AI 腔、口语化和宣传化表达，更接近财务 BP / 经营分析负责人材料
- [ ] 建议已细化为具体动作、对象和推进要求，而非空泛口号

### 7. 模板与引用
- [ ] 完整报告场景已先读取 `/assets/financial-analysis/biz-analysis-report.md`
- [ ] 需要写作规范时再读取 `report-generation.md`
- [ ] 需要更专业分析句式时再读取 `analysis-method.md`
- [ ] 需要补充报告末尾的结构化图表配置时，已读取 `chart-guidance.md`

## 响应风格

专业、简洁、结论先行、面向管理层；避免纯数字堆砌，语言需正式、克制，接近经营分析汇报材料。
