# 执行清单

只保留任务推进顺序与自检项；参数细节看 `metrics.md`，完整报告写法看 `report-generation.md`，判断与归因表达看 `analysis-method.md`。

仅在“经营分析 / 对比 / 诊断 / 报告”场景使用本清单。若用户只是查某节点某期间某指标，直接走轻量取数路径，不必套用完整分析清单。

## 1. 前置确认
- [ ] 在执行任何工具前，已先和用户确认本次范围、期间、目标、口径
- [ ] 已明确分析对象、时间范围、分析目的
- [ ] scope 不清或已变更时，已调用 `resolve_org_nodes`
- [ ] 多候选节点已让用户确认

## 2. 查询组织
- [ ] 若为完整报告，已先读取报告模板，并整理出章节所需指标名、期间、统计口径
- [ ] 优先使用 `query_with_hierarchy`
- [ ] 分析任务默认覆盖学年预算与突围考核（内部参数 `fone` 与 `tuwei`）
- [ ] 分析任务默认补齐当月、上月、累计
- [ ] 无依赖查询已优先并行
- [ ] 已复用已有结果，无重复同参调用
- [ ] 同一路径的 `read_file` 已最多读取一次，未把 reference 重复读取当作流程步骤
- [ ] 查询参数已显式带上模板需要的关键指标名，未因漏传指标导致假性缺数

## 3. 指标覆盖
- [ ] 已覆盖核心经营指标：`revenue`、`gross_profit`、`gross_margin`、`pretax_profit`、`pretax_margin`
- [ ] 完整分析默认补齐人力与费用细项，而非只看单一成本项
- [ ] 返回中的 `target_value`、`completion_rate`、`diff`、`yoy` 已纳入分析
- [ ] 突围考核章节已额外核对毛利率、税前利润率等结构性指标是否一并取回

## 4. 数据检查
- [ ] 空结果已排查节点、期间、口径、指标
- [ ] 累计 period 已取自 Runtime Data Context 的 `cumulative_periods`
- [ ] 缺失或矛盾数据已显式提示，并降低结论强度
- [ ] 若报告模板中的字段拟标 `【数据库暂无此数据】`，已按该字段对应指标名重新补查一次

## 5. 输出检查
- [ ] 达成率、差额、同比、判断均已绑定明确口径
- [ ] 当月与累计未混写
- [ ] 已先做聚合和可直接计算的衍生指标，再输出结论
- [ ] 若为完整报告，已先读取模板与 `report-generation.md`
- [ ] 只有用户明确要求图表配置时，才读取 `chart-guidance.md`
- [ ] 结尾已补充 1-3 个与当前任务强相关的下一步建议
